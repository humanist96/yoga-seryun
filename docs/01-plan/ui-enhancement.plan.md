# Plan: UI/UX 리치니스 개선 — 모바일 · 감성 · 전환 · 콘텐츠 4축 강화

> Feature: `ui-enhancement` · Phase: Plan · 작성일: 2026-07-15

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 사이트의 브랜드 감성(연꽃·호흡 모션)은 완성도가 높으나, ① 모바일에 내비게이션이 없고 ② 시간표가 예약과 연결되지 않으며 ③ 스크롤 여정에 시그니처 인터랙션이 히어로 이후 급격히 옅어지고 ④ 첫 방문자의 불안(뭘 입지? 어떻게 진행되지?)을 풀어주는 콘텐츠가 FAQ 텍스트에만 갇혀 있다. |
| **Solution** | 4축 개선 — (A) 모바일 경험: 하단 도크 내비 + 스티키 예약 바 + 이미지 파이프라인, (B) 감성 리치니스: 연꽃 개화 스크롤 프로그레스 + 시간대 무드 히어로 + "함께 한 호흡" 인터랙티브, (C) 전환 UX: 시간표→예약 직결 + 다가오는 수업 라이브 배너 + 예약 3스텝 시각화, (D) 콘텐츠 확장: 첫 방문 타임라인 + 공지 배너 시스템 + 강사 섹션(데이터 대기). |
| **Function UX Effect** | 모바일 방문자가 엄지 하나로 탐색→수업 확인→예약까지 도달하고, 스크롤 내내 "숨 쉬는 사이트"라는 브랜드 체험이 유지되며, 예약 직전의 심리적 장벽(예약비 1만원)이 시각적으로 해소된다. |
| **Core Value** | 네이버플레이스·인스타 유입(대부분 모바일)의 무료체험 예약 전환율 상승 + 체류시간·재방문 증가. |

## 1. 현재 상태 진단 (코드 기준)

### 잘 되어 있는 것 (유지·계승)

- **호흡 모션 시스템**: 들숨 4초·날숨 6초 원, 낙하 꽃잎, 필름스트립 — 순수 CSS 구동으로 '동작 줄이기' 기기 대응까지 완료
- **갤러리**: 스택→스프레드 연출, 라이트박스(키보드·스와이프·포커스 이동), 무한 필름스트립
- **시간표**: 요일 탭(모바일)/그리드(PC), KST 기준 "다가오는 수업" 하이라이트
- **전환 장치 기본기**: 히어로·내비·Voices·FirstClass 4곳의 예약 CTA, 플로팅 톡톡·전화
- **신뢰 블록**: 리뷰 키워드 바 차트 + 실제 리뷰 6건 + 85건 카운트

## 2. 개선안 상세 — 4축

### A. 모바일 경험 심화

**A1. 하단 도크 내비게이션 (모바일 전용)** — G1 해결
- 화면 하단에 liquid-glass 도크: `수업 · 시간표 · 체험 · 공간 · 길` 5개 앵커 + 스크롤 스파이(`IntersectionObserver`로 현재 섹션 `aria-current` 표시, 활성 항목에 연꽃 도트)
- 스크롤 다운 시 축소(라벨 숨김·아이콘만), 업 시 복원 — Navbar의 hide-on-scroll과 동일 문법
- `env(safe-area-inset-bottom)` 대응, FloatingContact와 겹치지 않게 우측 여백 재배치
- 신규 파일 `components/MobileDock.tsx` (햄버거 메뉴보다 원탭 접근이 요가 타깃층에 적합)

**A2. 스티키 예약 바 (모바일)** — G3 해결
- 히어로 CTA가 뷰포트를 벗어나면 하단에서 슬라이드 업: "첫 수업 무료 체험 →" 한 줄 바
- A1 도크와 통합 설계 — 도크 상단에 CTA 스트립을 얹는 형태로 UI 중복 방지 (도크+바를 따로 띄우면 하단이 혼잡해짐)
- Voices·FirstClass 등 CTA가 이미 보이는 섹션에서는 자동 숨김 (`IntersectionObserver`)

**A3. 이미지 파이프라인 v2** — G4 해결
- 빌드 스크립트(`sharp`)로 hero·갤러리 9장 → AVIF/WebP + 480/960/1600w 3단 `srcset` 생성
- 히어로: `<link rel="preload" as="image">` + `fetchpriority="high"`, 갤러리는 현행 `loading="lazy"` 유지
- 폰트 3종 CDN `preconnect` 확인·보강
- 목표: 모바일 LCP < 2.5s, 총 이미지 전송량 40%+ 절감

**A4. 라이트박스 모바일 마감**
- 핀치 줌(2단계: 더블탭 확대/원복), 상단 닫기 영역 확대, safe-area 패딩
- 포커스 트랩 추가(G7) — Tab/Shift+Tab 순환

### B. 감성·비주얼 리치니스

**B1. 연꽃 개화 스크롤 프로그레스** — 브랜드 시그니처를 여정 전체로 확장 (G6)
- 우측(모바일은 도크 좌측 끝)에 작은 연꽃 SVG — 스크롤 진행도에 따라 꽃잎이 한 장씩 벌어지고, 푸터 도달 시 만개
- `useScroll` progress → SVG 꽃잎 path 5장 순차 회전·전개. 클릭 시 맨 위로
- "스크롤 = 수련의 여정 = 개화"라는 내러티브를 UI로 번역한 장치

**B2. 시간대 무드 히어로** — "Lotus at Dawn" 컨셉의 완성
- KST 시각 기준 3무드: 새벽·아침(5–11시) 웜 화이트 그대로 / 낮(11–17시) 밝은 채도 / 저녁(17시–) 앰비언트 글로우를 플럼·앰버 톤으로 전환 + 인사말 교체("오늘 하루를 잘 마치셨나요")
- 구현은 CSS 변수 오버라이드 한 겹(`data-mood` 어트리뷰트)이라 저비용 — 색·인사말·글로우 색상만 스왑
- 저녁 유입(퇴근길 검색)이 많은 로컬 비즈니스 특성상 "지금 나에게 말 걸어주는" 체감 효과가 큼

**B3. "함께 한 호흡" 인터랙티브** — 보는 모션에서 참여하는 모션으로
- 히어로의 숨 쉬는 원에 조용한 어포던스("원을 눌러 한 호흡") → 탭하면 30초 가이드 모드: 원이 커지며 "들이쉬고 — 4", 작아지며 "내쉬고 — 6" 텍스트 동기화, 3회 반복 후 "이 호흡을 매일, 세련에서" + 체험 CTA
- 명상 스튜디오만 할 수 있는 차별화 인터랙션이자 CTA로 자연 연결되는 브랜드 체험
- 선택: 옵트인 싱잉볼 톤(Web Audio 신스, 파일 불필요) — 무음 기본, 아이콘으로만 노출

**B4. 마이크로 인터랙션 패스**
- CTA 호버 시 꽃잎 1장이 피어오르는 파티클(기존 Petals SVG 재사용), 내비 링크 언더라인 growth
- 섹션 경계: 직선 border 대신 완만한 곡선 SVG 디바이더 1종을 Classes↔Schedule, FirstClass↔Gallery에 적용 (LotusDivider와 톤 통일)
- Voices 리뷰 카드: 고정 그리드 → 느린 자동 흐름 캐러셀(필름스트립과 동일한 CSS 마퀴 문법, 호버 정지) + 85건 숫자 카운트업(영상 씬과 모션 언어 통일)

### C. 전환율(예약) UX

**C1. 시간표 → 예약 직결** — G2 해결
- 수업 셀 탭 → 바텀 시트(모바일)/팝오버(PC): 수업 설명(LEVELS description 재사용)·강사·레벨 + "이 시간에 체험 예약하기"(네이버 예약 딥링크) + "다른 시간 보기"
- 셀이 인터랙티브해졌음을 알리는 어포던스(호버 라이즈 + 우하단 미세 화살표)
- `ClassDetailSheet.tsx` 신규, 데이터는 기존 `schedule.ts`·`content.ts` 그대로

**C2. 다가오는 수업 라이브 배너**
- `findNextClass` 결과를 시간표 상단(+히어로 하단 보조)에 문장으로: "오늘 18:30 인요가(나영 선생님) — 3시간 후 시작 · 체험 가능"
- 남은 시간은 분 단위 1회 계산(실시간 카운트다운은 조급함을 줄 수 있어 지양 — 브랜드 톤 유지)
- 탭하면 C1 시트 오픈

**C3. 예약 3스텝 시각화** — G5 해결
- FirstClass 카드 안에 가로 스텝퍼: `① 네이버로 예약 (예약비 1만원)` → `② 수업 참여` → `③ 전액 환불` — "부담은 노쇼 방지용, 오시면 0원"을 그림으로
- Voices 하단 CTA의 각주도 동일 컴포넌트 축약형으로 통일

**C4. 플로팅 문의 온보딩**
- 첫 진입 6초 후 톡톡 버튼 옆에 말풍선 1회 노출("궁금한 건 톡톡으로 편하게 물어보세요", 8초 후 자동 소멸, 세션 내 재노출 없음 — 메모리 변수로 관리)

**C5. FAQPage JSON-LD 추가** — G8 해결
- `FAQS` 데이터를 빌드 타임에 JSON-LD로 직렬화해 삽입 — 검색 리치 결과로 유입 단계 전환율까지 커버

### D. 콘텐츠 구조 확장

**D1. "첫 수업은 이렇게 진행돼요" 타임라인**
- FirstClass 섹션 확장: `20분 전 도착·차 한 잔 → 몸 상태 상담 → 60분 수련 → 마무리 명상` 4단계 세로 타임라인(모바일)/가로(PC), 각 단계에 갤러리 사진 1장 매칭
- FAQ에 흩어진 정보(입장 20분 전, 준비물 없음, 복장)를 여정 형태로 재조립 — 첫 방문 불안 해소가 목적

**D2. 공지·이벤트 배너 시스템**
- `content.ts`에 `ANNOUNCEMENT` 옵셔널 객체(문구·링크·기간) — 값이 있으면 Navbar 아래 얇은 배너 자동 노출, 기간 만료 시 자동 숨김
- 운영자(원장님)가 코드 한 줄로 "일요일 스페셜 명상 오픈" 등을 걸 수 있는 비개발자 친화 장치

**D3. 스페셜 프로그램 카드화** — G9 해결
- 시간표 하단 각주 문단 → 카드 2장: `평일 낮 (14–17시)` 개인레슨·특화프로그램 / `일요일` 스페셜 명상(야외·테마·원데이). 각각 "상담으로 문의" CTA(톡톡 링크)

**D4. Teachers 섹션 (데이터 대기 — 스캐폴드만)**
- README TODO의 강사(나영·시소) 약력 확보 전제. `content.ts`에 `TEACHERS` 스키마와 빈 배열을 먼저 정의하고, 데이터가 채워지면 Schedule 뒤에 섹션 자동 노출
- 시간표 셀 강사명 → 해당 카드 앵커 연결

**D5. 채널 최신 소식 (선택, 후순위)**
- 인스타 임베드는 성능·API 제약이 크므로, `content.ts`에 수동 큐레이션 3건(썸네일+링크) 형태의 "요즘 세련" 블록으로 대체 — content-pipeline(블로그·릴스 산출물)과 연계해 발행 시 함께 갱신

|------|------|------|
| 하단 UI 밀도 | 도크+CTA+플로팅 버튼이 모바일 하단에서 경합 | A1·A2 통합 설계 + FloatingContact 위치를 도크 위로 승격, 실기기 검수 필수 |
| 시간대 무드의 저녁 톤 | 어두운 톤이 "밝고 쾌적한 공간" 리뷰 포인트와 충돌 가능 | 배경은 웜 화이트 유지, 글로우·인사말만 전환하는 보수적 버전으로 시작 |
| 호흡 가이드 사운드 | 자동 재생 소리는 금물 | 기본 무음, 명시적 옵트인 아이콘, 세션 기억 없음(항상 무음 시작) |
| 시간표 시트의 예약 딥링크 | 네이버 예약은 수업별 슬롯 딥링크 미제공(단일 예약 페이지) | 시트에는 "예약 후 희망 시간 메모" 안내 문구 첨부, 톡톡 문의 병기 |
| 이미지 빌드 스크립트 | public 정적 파일 → 생성물 관리 필요 | 원본은 `media-src/` 보관, 생성물만 `public/media/` — .gitignore 검토 |
| 강사 섹션 | 약력·프로필 사진 미확보 | 스키마만 선구현, 데이터 확보 시 노출 (README TODO 연동) |

## 5. 완료 기준 (Acceptance Criteria)

- [ ] 모바일에서 하단 도크로 5개 섹션 원탭 이동이 가능하고, 현재 섹션이 표시된다
- [ ] 히어로 이탈 후에도 모바일 화면에 예약 CTA가 상시 노출된다 (CTA 중복 섹션에서는 자동 숨김)
- [ ] 시간표의 모든 수업 셀에서 2탭 이내에 네이버 예약 페이지에 도달한다
- [ ] "다가오는 수업" 배너가 KST 기준 올바른 수업과 남은 시간을 표시한다
- [ ] 예약비 환불 정책이 3스텝 그래픽으로 FirstClass에 표시된다
- [ ] 스크롤 진행에 따라 연꽃 프로그레스가 개화하고, 클릭 시 최상단으로 이동한다
- [ ] 17시 이후 접속 시 히어로 무드(글로우·인사말)가 저녁 버전으로 전환된다
- [ ] 호흡 가이드가 탭으로 시작·종료되고 종료 화면에서 체험 CTA로 연결된다
- [ ] 히어로·갤러리 이미지가 AVIF/WebP srcset으로 서빙되고 모바일 Lighthouse LCP < 2.5s
- [ ] 라이트박스 포커스 트랩이 동작하고, FAQPage JSON-LD가 유효성 검사를 통과한다
- [ ] 기존 시그니처(숨 쉬는 원·꽃잎·필름스트립)의 '동작 줄이기' 대응 원칙이 신규 모션에도 유지된다
- [ ] `npm run build` 통과, 신규 인터랙션 전부 키보드 접근 가능
